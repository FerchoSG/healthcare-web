# Decisiones del contrato

## 1.0.0 — 2026-10-02

- Una línea clínica estable: azul petróleo, superficies planas y neutras, radios moderados.
- Tokens JSON canónicos; derivados CSS generados; semántica única de citas.
- Pila de sistema explícita para una implementación sencilla y legible; no fuentes declaradas sin carga.
- Identidad de clínica personalizable sin redefinir estados, controles o estructura operativa.
- AGENTS, checklist y gate de contraste/diff para continuidad. Las recomendaciones locales de variar estética por generación quedan subordinadas al contrato solicitado por el usuario.
- La referencia es ilustrativa y no reemplaza el producto. La migración completa sigue el orden de PLAN y se realiza en esta misma iteración.

## Aplicación — 2026-10-03

- Migradas todas las vistas actuales, controles comunes, reservas y portal.
- Agenda con día/semana, filtro por profesional y citas simultáneas visibles.
- Expediente a pantalla completa, historial seleccionable y aviso de cambios sin guardar.
- Catálogo público obtenido de la API y reserva con avance explícito por pasos.
- Eliminados controles ficticios, métricas de relleno y texto técnico en los flujos de clientes.
- Conservadas API, permisos y utilidades de zona horaria existentes.
- La evidencia y los límites de la verificación se registran en VERIFICATION.md.

## Formato para próximas decisiones

Fecha / versión / problema observado / evidencia / patrón o token afectado / decisión / combinaciones de contraste / pantallas que deben migrarse / validación realizada.

Incrementar patch para corrección sin cambiar contrato; minor para componente/token compatible; major para cambio de identidad o interacción de alcance amplio. Toda modificación debe actualizar referencia y checklist aplicable.
